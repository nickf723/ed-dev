# Computer Science remaster contract

## Educational job

The Computer Science root is a six-branch navigation hub and execution-trace
lesson. It helps a learner move between physical machinery, software,
algorithms, intelligent systems, formal limits, and networks/security; follow
represented state through a procedure and interface; distinguish behavior from
correctness; calculate a finite state space; and name the property a security
claim protects.

It is not a programming tutorial, a product catalog, a generic terminal
dashboard, proof that a passing example is correct, or a substitute for any of
the six active branch pages.

## Registry and navigation contract

`COMPUTER_SCIENCE_CURRICULUM` owns exactly six active direct branches in this
order:

1. Hardware Architecture
2. Software
3. Algorithms & Data
4. Artificial Intelligence
5. Computation Theory
6. Security & Cryptography

The page derives labels, descriptions, statuses, hrefs, and breadcrumbs from
the registry and fails loudly when the model order drifts. The computing stack
is navigation; the runtime loop, principles, assessment, and repository shelf
are reference or lesson content.

## Lesson flow

1. Six-layer computing stack and shared computation loop
2. Representation, execution, and composition principles
3. Four-trace evidence review
4. Code, protocol, and vulnerability repository boundaries

Major sections use 96px scenery corridors so the static state-flow field can
remain visible between foreground surfaces.

## Shared model and exact practice

`computerScienceModel.ts` owns direct branch parity, bounded bit-pattern
arithmetic, and four evidence answers. `calculateBitPatterns` accepts safe
integer bit counts from 0 through 52 and otherwise returns 0.

The exact practice fixture is:

`8 independent bits = 2^8 = 256 distinct patterns`

The count does not determine whether those patterns mean unsigned integers,
characters, pixels, flags, instructions, or another encoding. The remaining
traces test a sorting contract, a versioned/paginated API contract, and
integrity versus confidentiality and availability.

## Vocabulary ownership

Computer Science owns six broad terms. Each direct branch owns two specialized
terms, for 18 unique terms in the subtree. Stable legacy IDs for polymorphism,
recursion, pointer, and latency remain unique but now belong to the narrowest
direct branch that teaches them. The Computer Science root and Formal Science
drawer aggregate branch terms through curriculum containment with source-node
provenance.

## Visual and hydration contract

The root background is a deterministic server-rendered SVG execution field. It
shows encoded input state entering three buses, a transformation core, and
layered output interfaces. It uses no canvas, viewport reads, random values,
timers, animation frame, or hydration-time drawing.

The evidence review initializes from fixed model data. Required interface copy
stays at least 11px, focus is visible, and motion is not necessary to understand
the route.

## Repository boundaries

The page links to official sources and performs no render-time fetch:

- [GitHub repository REST API](https://docs.github.com/en/rest/repos/repos) for
  code-repository identity and metadata;
- [RFC Editor search](https://www.rfc-editor.org/search/) for protocol
  documents, status, update/obsolescence relationships, and errata;
- [NVD vulnerability API](https://nvd.nist.gov/developers/vulnerabilities) for
  defensive vulnerability records, sources, applicability statements, and
  versioned metrics.

A future adapter must preserve provider identity, stable record ID, relevant
version or revision, source URL, pagination, response/API version, refresh
context, and field-level source distinctions. Stars are not code quality; RFC
publication is not current-standard status or implementation conformance; a CVE
or score is not proof of local exposure, exploitability, or priority.
