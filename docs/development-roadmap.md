# Education Station 64 Development Roadmap

This roadmap turns `keep building` into a concrete production queue. It works with the Development Constitution and does not override preservation, parent-first, readability, navigation, or background-quality gates.

## Operating model

The user acts primarily as creative director. Autonomous development should not require the user to select every next page or catch routine implementation defects.

For each development round:

1. choose the highest-value unfinished parent from the current phase;
2. inventory and preserve its existing distinctive systems;
3. repair ancestry or curriculum structure before expanding descendants;
4. develop the parent to the constitution's Developed standard;
5. validate and publish before beginning the next target;
6. record the result here so future rounds resume from repository state rather than conversation memory.

User feedback should be treated primarily as directional design input. Routine CSS, responsive, type, content-boundary, navigation, and build defects should be caught and repaired autonomously.

## Page maturity

- **Foundation**: route exists and ontology is roughly correct.
- **Developed**: distinctive parent world, prominent trustworthy navigation, useful academic structure, at least one strong explanatory or interactive centerpiece, readable and responsive composition.
- **Polished**: developed page has survived visual review and targeted feedback with no known constitutional compromises.
- **Parked**: polished page is left alone unless broken, structurally affected by later work, or revisited for a genuinely new idea.

A page does not need to be unimprovable to graduate. Endless cosmetic revision is not the goal.

## Phase B: signature branches

After Phase A coverage is healthy, develop 2 to 4 representative children beneath each strong parent. Children should specialize the parent's environmental family rather than duplicate it.

Priority examples:

- Mathematics: curriculum-sequenced Algebra and foundational lessons
- Computer Science: Algorithms branches and core Software / Architecture branches
- Biology: representative cellular, organismal, ecological, and evolutionary children
- Social Science: one strong child per major scale or methodology family
- Humanities: one analytical and one creative / interpretive child per major field where appropriate
- Engineering: mechanical, civil, electrical, and software as contrasting specializations

## Phase C: curriculum depth

Systematically fill learning sequences, beginning with mathematics because prerequisite order is unusually important there. Use curriculum nodes, prerequisites, and sequence navigation rather than creating isolated attractive pages.

## Phase D: network intelligence

Build cross-subject relationships:

- prerequisites and recommended next steps;
- concept backlinks;
- related ideas across domains;
- vocabulary and symbol reuse;
- interdisciplinary trails;
- learner progress and route memory.

## Phase E: authoring machine

Improve Page Foundry and reusable world / widget systems so later page creation becomes faster without making pages more generic. Reuse primitives, not finished compositions.

## Autonomous completion report

At the end of a working session, report only:

- which parents or children reached a new maturity state;
- what distinctive world / interaction was preserved or added;
- current `studio` head;
- honest validation status;
- the next queued target.

The roadmap is a living production document. Update it when a page graduates or when user direction changes the queue.
